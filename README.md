# rugatha-trello：一起整理工作、追蹤進度

今天有哪些事要做？哪件事正在處理？完成的工作放在哪裡？rugatha-trello 可以讓團隊把這些資訊放在同一個地方。

你不需要用過 Trello。只要把每一件工作想成一張小卡片，再把卡片放進適合的進度欄位，就能開始使用。

[進入網站](https://rugatha.github.io/rugatha-trello/)

## 第一次來，怎麼開始？

先按右上角的「使用 Google 登入」，選擇你要使用的 Google 帳號。

如果登入後看到「尚未取得工作空間權限」，先別擔心：這個網站需要由管理員開通，登入 Google 後還不能直接加入。請聯絡團隊的管理員，告訴對方你的 Google 信箱，以及你需要參與的工作。管理員開通後，回到網站按「重新整理」就可以再試一次。

如果看到「沒有可存取的看板」，請管理員幫你加入需要的看板。

登入時如果出現「設定顯示名稱」，填入讓團隊認得你的名字，按「儲存名稱」。之後也能隨時修改。

**請使用管理員幫你開通的那個 Google 帳號。** 如果選錯帳號，點右上角帳號名稱，按「登出 Google」，再重新登入。

## 把看板想成一面工作牆

登入後，你會在左側「我的看板」看到可以參與的專案。點一個名稱，就能打開它。按「我的看板」旁的「↕」，用上下箭頭調整看板順序，再按「儲存順序」。排序只影響自己的清單，會隨帳號保留；新加入的看板排在最後。

一個看板就像一面工作牆。例如「活動籌備」看板，可以分成「待辦」、「進行中」、「已完成」三欄。每一欄稱為一個「階段」，每張卡片則代表一件工作。

假設你要確認活動場地，可以建立一張「確認活動場地」卡片：還沒開始時放在「待辦」，開始聯絡時移到「進行中」，確認完成後移到「已完成」。團隊一眼就能知道進度。

點開卡片，可以看到更詳細的說明、負責人、截止日期、待辦事項、附件與留言。手機上如果看不完所有階段，可以左右捲動。

## 我可以做哪些事？

點右上角的帳號名稱，就能查看自己的身分。畫面上會用英文顯示角色，可以對照下面的說明。

| 你的身分 | 你可以怎麼使用 |
| --- | --- |
| 一般會員（Member） | 閱讀看板、搜尋工作、查看卡片及下載附件。 |
| 閱讀者（Viewer） | 和一般會員一樣，適合查看進度與閱讀資料。 |
| 編輯者（Editor） | 除了閱讀，也能新增與修改卡片、移動工作、留言、上傳附件及整理看板。 |
| 管理員（Admin） | 除了編輯，也能建立看板、安排負責人，並協助一般會員加入或調整使用權限。 |
| 擁有者（Owner） | 除了上述操作，也能管理其他管理員與所有會員的身分。 |

每個人看到的看板可能不同。如果你需要的看板沒有出現，請管理員幫你加入。如果你能閱讀卻不能修改，而工作需要你編輯，也請管理員協助調整身分。

下面先介紹每個人都能使用的閱讀功能，再說明編輯者與管理員的操作。

## 閱讀者：找到你要看的工作

從左側選擇看板，點開卡片就能閱讀內容。附件區的檔名可以點擊下載；如果附件是其他網站的連結，會開啟該網站，有時需要另外登入。

卡片很多時，不必逐張尋找：

- 在上方搜尋框輸入關鍵字，尋找目前看板中標題或說明符合的卡片。
- 按「指派給我」，只看目前看板中安排給你的工作。
- 使用截止日期選單，查看「已逾期」、「未來 7 天」或「未設定日期」的工作。
- 想回到完整清單，按「清除篩選」。

搜尋與篩選可以一起使用。如果突然找不到卡片，先清除篩選，再確認自己是不是在正確的看板。

閱讀者可以查看留言、待辦事項及「封存項目」，但不能留言、勾選待辦或修改內容。

## 編輯者：把工作記下來，再更新進度

管理員與擁有者也可以使用這一節的功能。

### 新增第一張卡片

1. 打開要工作的看板。
2. 在想放置工作的階段下方，按「新增卡片」。
3. 輸入清楚的工作名稱，例如「整理活動報名名單」，再按「儲存」。
4. 點開卡片，補上需要做什麼、相關資訊或注意事項。

上方的「建立卡片」也能新增工作，卡片會先放在看板的第一欄。

卡片裡的文字改完後，點一下其他欄位，網站就會自動儲存。離開前，留意看板上方是否仍顯示正在儲存，或出現儲存失敗的訊息。

### 工作開始了，怎麼更新？

把卡片拖到下一個階段即可。也可以打開卡片，選擇「所在階段」與「牌卡位置」，再按「套用階段與位置」；可指定放在該階段的第幾張，用手機操作時也比較方便。

你可以在卡片裡設定「截止日期」，並展開「選擇標籤」多選清單，讓工作更容易辨認；平時只顯示已選標籤。完成後，可按標題左側的圓點或勾選「已結案」：空心圓表示未結案，綠色勾選圓表示已結案。移動到完成階段不會自動結案，結案以這個勾選狀態為準。

如果需要安排負責人，請管理員協助。卡片裡的負責人清單可以查看，但編輯者不能自行更改指派。

### 把大工作拆成小步驟

在「待辦事項」輸入一個步驟，按「＋」新增。例如「整理活動報名名單」可以拆成「下載名單」、「確認重複報名」、「整理聯絡方式」。完成一項就勾選一項。

不需要的待辦可以按旁邊的「×」刪除，刪除後無法從封存項目找回。

### 留下進度與相關檔案

在「留言與討論」輸入內容，按「送出留言」，讓其他人知道進度或需要協助的地方。

需要提供資料時，按「上傳附件」選擇檔案，可以一次選多個。每個檔案最多 20 MiB，支援常見圖片、PDF、純文字、ZIP，以及 GLB、STL 檔案。請等到出現「附件已儲存」再離開。如果上傳失敗，可以按「重試未完成附件」。

圖片附件還可以按「設為封面」，讓圖片直接顯示在看板上的卡片上。

### 整理看板

看板名稱旁的「⋯」可以修改看板名稱、說明與配色。這些調整會讓同一看板的其他成員一起看到。

需要不同的工作流程時，按最右側「新增階段」增加一欄。階段名稱旁的「⋯」可以改名或調整欄位順序。刪除階段則需要請管理員處理。

### 重複工作可以複製，暫時不用可以封存

打開卡片，按「複製卡片」，選擇目標階段與副本位置，再儲存，就能用原本的內容建立一張副本。副本會保留說明、標籤、日期、完成勾選與待辦事項；負責人、附件與留言需要另外處理。使用副本前，記得檢查日期與完成勾選是否需要更新。

「封存」是把暫時不需要的內容收起來，之後仍能找回。卡片詳情裡的「封存卡片」可以收起卡片，附件旁的「×」可以收起附件。

要找回時，在看板按「封存項目」，再按「復原牌卡」或「復原附件」。如果整張卡片已經封存，先復原卡片，再找它的附件。編輯者、管理員與擁有者都能復原；閱讀者只能查看。

整個專案暫時不用時，Owner 可在看板設定按「封存看板」。之後從左側「封存看板」找到它，打開看板設定，按「復原看板」即可。

## 管理員：讓團隊加入並安排工作

### 建立團隊的新看板

1. 在左側「我的看板」旁按「＋」。
2. 填寫名稱與說明，選擇配色。
3. 勾選要一起參與的會員，再儲存。

你會自動加入新看板。看板會先準備好「待辦」、「進行中」、「已完成」三個階段，之後可以依團隊需要調整。加入看板的成員會沿用原本身分，例如閱讀者加入後仍然只能閱讀。

### 邀請新成員

1. 在左側打開「會員管理」，按「邀請會員」。
2. 填入對方的顯示名稱與準備登入的 Google 信箱。
3. 選擇適合的身分，勾選對方需要的看板，按「建立邀請」。
4. 找到剛加入的會員，按「管理」，將「會員狀態」改成「核准／啟用」，再按「儲存會員權限」。
5. 告訴對方網站網址，以及應該使用哪個 Google 帳號登入。

**建立邀請後，網站不會自動寄信，而且需要完成核准，對方才能使用。**

### 調整成員的使用範圍

在「會員管理」找到對方，按「管理」，就能修改身分、勾選看板，或將狀態改成「停用」。如果對方不再參與某個專案，取消該看板的勾選即可；如果不再使用整個網站，可以停用會員。

管理員（Admin）可以管理一般會員、閱讀者與編輯者，也只能調整自己能查看的看板。需要調整管理員、擁有者或其他看板時，請擁有者（Owner）處理。變更擁有者時，必須保留至少一位仍在使用網站的擁有者。

### 安排卡片負責人

打開卡片，按「管理負責人」，勾選要負責的人並儲存。取消勾選，就能移除指派。

如果找不到某位成員，先確認對方已核准，並已加入這個看板。看板或卡片已封存時，請先復原再修改負責人。

### 刪除不需要的階段

先把階段裡的卡片移到其他欄位，包含已封存的卡片也要先處理。階段清空後，點階段名稱旁的「⋯」，按「刪除此階段」。每個看板至少要保留一個階段。

## 換名字、換主題與登出

點右上角帳號名稱，可以開啟個人設定。

- 在「大頭貼」選擇 JPG、PNG 或 WebP 圖片（最多 5 MiB），會自動置中裁切並儲存；也能按「移除大頭貼」恢復名字首字。團隊在成員名單、卡片及留言都能看到圖片，其他成員重新整理後可看到更新。
- 按「修改顯示名稱」，更換團隊看到的名字。
- 在「個人主題」選擇明亮或深色，讓閱讀更舒適。這只會影響你自己的畫面。
- 按「登出 Google」離開帳號。使用共用電腦後，記得登出。

左側「工作空間成員」與看板上的「會員資訊」可以查看成員名稱。要邀請新成員或調整身分，管理員請使用「會員管理」。

## 遇到問題時

| 遇到什麼狀況？ | 可以怎麼做？ |
| --- | --- |
| 登入視窗沒有出現 | 允許瀏覽器開啟此網站的彈出式視窗，再按一次登入。 |
| 登入後看不到看板 | 確認 Google 帳號是否正確，再請管理員協助開通或加入看板。 |
| 找不到某張卡片 | 清除搜尋與篩選，確認看板，或到「封存項目」找找看。 |
| 按鈕不能按 | 等待載入或儲存完成；如果仍不能操作，可能需要管理員調整你的身分。 |
| 顯示儲存失敗 | 先確認網路連線，記下要保留的文字，再重新整理並重新修改。 |
| 提示內容已被其他人修改 | 重新整理，先閱讀對方的最新內容，再繼續修改。 |
| 附件打不開 | 確認網路連線；如果是外部連結，可能需要登入來源網站，或請提供者更新連結。 |
| 剛取得權限，畫面卻還沒更新 | 按網站內的「重新整理」。 |

網站需要連線才能儲存。多人一起工作時，關閉卡片視窗可以查看其他人的最新更新。

管理員調整你的身分或能查看的看板時，編輯視窗可能關閉。重新整理、切換帳號或權限變動前，尚未送出的文字請先自行保留。

如果仍需要協助，請把操作步驟與畫面上的錯誤訊息告訴團隊管理員。

## 專案檔案與安裝

前端入口為根目錄的 `index.html`；程式集中於 `src/`，樣式與圖示位於 `assets/`。工作清單見 [docs/to-do.md](docs/to-do.md)，整理與保留檔案的理由見 [docs/project-structure.md](docs/project-structure.md)。Firebase 設定、規則、npm 設定及 PWA 的 manifest／service worker 保留於根目錄。

網站提供 PWA manifest，可從支援的瀏覽器安裝或加入主畫面，使用 `assets/rugatha-trello-icon.png` 縮小後的圖示。部署後需透過 HTTPS 存取；本機驗證可使用 localhost。離線啟動使用瀏覽器預設錯誤頁，不提供離線內容；service worker 不攔截請求，更新時會清除舊版離線提示快取。規格參考：[MDN manifest](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference)、[service worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)。

Owner 可在看板設定封存／復原看板；永久刪除須先封存並輸入名稱確認。封存牌卡的永久刪除位於「封存項目」。詳見 [Owner 管理設計與部署狀態](docs/content-lifecycle.md)。


### 歡迎頁與看板會員頭像

每次進入或重新載入網頁會先顯示歡迎頁，點選左側看板才進入看板；點「專案看板」可回到歡迎頁。歡迎頁使用森林綠底、暖沙色文字。看板右上角的頭像只顯示仍啟用且可存取該看板的會員，沿用最多五位的顯示方式；資格與可指派負責人的名單一致。此篩選需同步部署前端與更新後的 `management:listDisplayMembers`（後端已於 2026-10-16 部署）；名冊僅附上目前登入者可存取看板內的會員資格，不回傳其他看板權限或私人設定。

### 個人排序與大頭貼的部署／驗證

新增設定使用既有 `members` 文件的 `boardOrder` 與 `avatar`，無須資料遷移。大頭貼為 160×160 JPEG 縮圖（最多 50,000 字元），只在有權限的會員名單傳送。部署時需同步更新前端、`firestore.rules` 與 `listDisplayMembers` Cloud Function；只更新前端會因舊規則而無法儲存。

本機驗證：`npm test`、`npm run test:rules`、`npm run test:management`。執行 `python3 scripts/serve-phase5-test.py` 後開啟 `http://127.0.0.1:8005/tests/browser/preferences.html`，按「執行測試」可驗證排序、實際圖片縮放與手機設定畫面；此頁使用記憶體資料，不會存取正式 Firebase。


### 留言標註與通知

牌卡留言輸入 `@` 可搜尋並選取會員，也支援上下鍵、Enter／Tab 選取及 Escape 關閉。候選名單僅包含有效且有該看板權限的會員（牌卡沿用看板權限）；後端送出時會再次驗證。標註以會員 ID 與文字位置儲存，編輯或刪除標註文字會取消該次標註，純文字輸入名字不會發送通知。留言權限沿用 Owner／Admin／Editor。

頂端「通知」顯示最近 100 則個人通知與其中的未讀數量。新增指派與被其他人標註時會產生通知，連線期間新通知另有即時提示；支援單則及整批設為已讀。點擊指派通知可開啟牌卡，標註通知會捲動並標示對應留言。失去權限、封存或刪除的牌卡不會被開啟。通知、留言與指派透過同一交易寫入，重試不會重複通知。

此功能需同步部署前端、`firestore.rules` 與 Functions `listMentionMembers`、`postComment`、`setManagedAssignees`，無須遷移既有資料；既有指派與留言不會補發歷史通知。通知存於 `workspaces/main/members/{memberId}/notifications`，僅本人可讀且只能修改已讀狀態，客戶端不能建立通知。本機驗證使用 `npm test`、`npm run test:rules`、`npm run test:management`。

2026-10-16 已部署上述三支 Functions 與 Firestore 規則，正式端點與 CORS 驗證通過；詳見 [通知後端部署紀錄](docs/notifications-deployment.md)。本次後端部署未發布 GitHub Pages 前端。

留言作者可在自己的留言旁選擇「編輯」或「刪除」（仍需具有有效看板編輯權限，封存中的牌卡不可修改）。編輯沿用留言輸入框與 @ 選單，支援取消，並顯示「已編輯」；刪除前需確認。兩者皆由 `manageComment` callable 驗證作者、看板權限與原始留言版本，避免覆蓋其他視窗的變更；刪除同步更新牌卡留言數。編輯僅通知新增的被標註者。需要部署新增的 `management:manageComment` 與更新後的前端，沿用既有 Firestore 規則。

附件上傳不限副檔名、MIME 類型或內容格式，每檔須大於 0 bytes 且不超過 20 MiB。瀏覽器無法辨識類型時使用 `application/octet-stream`。前端、附件 Functions 與 Storage 規則一致保留大小限制、會員／看板權限、上傳資料連結與檔案大小一致性檢查；部署時需同步發布前端、`storage.rules`、`beginAttachmentUpload` 與 `finishAttachmentUpload`。


### 甘特圖

從首頁左側「甘特圖」開啟 `gantt.html`，以看板 → 牌卡 → 清單項目查看時程，預設展開看板並顯示牌卡，清單項目維持收合；點選箭頭可逐層收合或展開。負責人預設為「負責人為我」，依登入會員 ID 篩選；可切換所有負責人或其他成員，並搭配看板、開始／結束日期篩選，時間軸固定使用週刻度。預設從開啟日當週的週日開始，跨越開始日的工作會保留並裁切時間條，結束日在範圍之前的項目需調整日期才能查看。未填結束日期時至少顯示六週，並涵蓋後續時程。已結案牌卡與已完成清單預設隱藏，勾選「顯示已結案的項目」可顯示；清除篩選會恢復上述預設。每張牌卡的名稱可連至 `index.html?board=…&card=…`，登入並通過看板權限檢查後自動開啟牌卡。清單負責人沿用牌卡；封存牌卡不列入，封存看板保留標示。甘特圖沿用登入會員的 `accessboard` 及既有 Firestore 看板讀取權限，登出、權限變更或同步錯誤會清除內容。

牌卡開始日為建立日期，結束日優先使用截止日；沒有截止日時，使用勾選「已完成任務」所記錄的 `completedAt`。取消完成會清除結案日期，再次完成則記錄新的日期。舊牌卡沒有結案紀錄時顯示「未記錄結案日期」，不以最後編輯時間代替，無須回填或遷移。截止日期編輯需同步發布前端與更新後的 `firestore.rules`，不需要新增 Functions。

清單文字支援 `2026/10/31`、`2026-10-31`、`2026年10月31日`、`10/31`、`10月31日` 與日期區間。沒有年份時，依牌卡建立年推算，日期早於開始日則取下一年，日期區間延續前一日期的年份並取最後一天。相對日期（如「明天」）、無效日期及無日期文字不推測，保留項目並顯示未辨識日期。日期以台北時區呈現，清單開始日沿用牌卡建立日。

驗證：`npm test`；執行 `python3 scripts/serve-phase5-test.py`，開啟 `http://127.0.0.1:8005/gantt-app` 可用記憶體假資料檢查篩選、收合、手機版及登出清除，不讀寫正式 Firebase。


甘特圖牌卡旁的「修改截止日期」僅提供仍被指派且有看板權限的負責人使用，支援台北時間的日期與時間，留空儲存可移除 deadline。包含 Member／Viewer 負責人；新增 Firestore 授權只允許修改 `due`、`updatedAt`、`updatedBy`，不授予其他內容編輯權限。封存或刪除中的看板／牌卡不可修改。儲存時重新檢查目前指派與原截止日期，其他欄位的同時編輯不會被覆蓋；衝突或失敗會保留輸入並提示重試。編輯視窗開啟時暫緩即時重載，切換帳號或權限同步錯誤則清除視窗。

新版需部署 `firestore.rules` 後，原本只有閱讀權限的牌卡負責人才能儲存 deadline。本機驗證涵蓋 `npm test` 與 Firestore 模擬器的 `tests/rules/firestore.test.mjs`。


### 看板標籤、位置與結案標記

牌卡詳情只顯示已選標籤；編輯者展開「選擇標籤」可多選或取消。舊版自動提供的設計、開發、內容、規劃、行銷預設項目已移除。看板成員可從「新增／管理標籤」新增名稱、自選顏色或調整既有標籤，顏色變更同步於同看板所有使用該標籤的牌卡。此例外只授予標籤定義管理，Member／Viewer 仍不能替牌卡勾選標籤或編輯其他內容。

「所在階段」搭配「牌卡位置」，按「套用階段與位置」才儲存；複製時也先選目標階段與第幾張。排序只更新被移動或複製的牌卡，不會重排整個看板。牌卡標題左側的空心圓／綠色勾選圓與「已結案」共用 `done` 狀態及 `completedAt`，與所在階段、是否設定截止日分開判斷。

看板成員管理標籤需同步部署新增的 Firestore 規則。新增的受限授權只允許一次調整一個 `labelDefinitions` 項目及其 `labelEditId` 識別欄位，不開放其他看板或牌卡寫入；封存與刪除中的看板不能使用。原有 Owner／Admin／Editor 的編輯權限沿用既有規則。
