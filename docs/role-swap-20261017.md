# 管理角色定義與遷移

自 2026-10-17 起，交換原有 owner／admin 的權限定義：

| 角色 | 範圍 |
| --- | --- |
| admin | 全站管理員；可管理所有會員角色及看板授權，執行原 owner 的看板生命週期操作。 |
| owner | 看板管理者；沿用原 admin 的權限，在已授權看板內管理工作與負責人，無法提升或管理 admin／owner。 |

後端保護改為至少保留一位有效 admin，包含並行降權／停用的情境。甘特圖不受牌卡指派限制的管理員截止日期編輯權，也改為 admin。前端的帳號角色與會員管理選單使用明確的中文說明。

正式資料只需遷移 Rugatha 一位：`owner` → `admin`。會員文件 ID、Google 信箱對應、7 個看板授權，以及 `assignable: false` 均保留；沒有建立新身分或更動牌卡指派。遷移使用 `scripts/swap-management-roles.cjs`，備份與結果存於忽略版控的 `attachments_export/maintenance/role-swap-20261017/`，以文件版本檢查防止覆寫並行變更或重複交換。

已部署並驗證：

- Firestore：以原正式規則為基底，僅交換角色名稱；未合併先前尚未部署的標籤／一般負責人截止日期授權。
- `listMembershipDirectory`、`saveManagedMembership`、`manageContentLifecycle`：皆為 ACTIVE，流量已切換至新版本。
- 已重新讀取正式會員資料，確認 Rugatha 是 admin、保有 7 個看板權限且不可指派。
- 185 項一般測試、48 項 Firestore 規則、17 項 Storage 規則、39 項會員／管理整合、7 項內容生命週期測試通過。
